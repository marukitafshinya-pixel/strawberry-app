# いちご狩り 予約・会計管理アプリ 開発計画

## 技術構成（提案）

| 役割 | 使うもの | ひとこと説明 |
|---|---|---|
| 画面 | Next.js（TypeScript）を「静的書き出し」 | Webページを作る道具。完成品はただのファイル群になるので、置くだけで動く |
| ログイン | Firebase Authentication | メール＋パスワードのログイン機能を借りる |
| データ保存 | Cloud Firestore | ネット上のデータベース（表計算の表のようなもの）。変更が即時に全端末へ届く |
| サーバー処理 | Cloud Functions | 「予約を受け付けてよいか」をお客様の端末ではなくサーバーで判定する小さなプログラム |
| 公開 | Firebase Hosting | 作った画面をインターネットに公開する場所 |
| いたずら対策 | Firebase App Check（reCAPTCHA） | ロボットによる大量送信を防ぐ仕組み |
| スタッフ画面 | PWA | Safariで「ホーム画面に追加」するとアプリのように使えるWebページ |

### 指示書の案からの変更点と理由
1. **Cloud Functions を使う（トランザクション単独ではなく）**
   お客様はログインしないため、Firestoreに直接書き込ませると入力チェックや連続送信の制限が難しくなります。
   予約受付・スタッフ追加・売掛の自動作成などをサーバー側で行い、その中でトランザクション
   （＝「残り人数の確認」と「予約の保存」を一体で行い、途中で他の人が割り込めない処理）を使います。
   ※ Cloud Functions の利用には Firebase の従量課金プラン（Blaze）が必要です。小規模なら無料枠内に収まる見込みですが、予算アラートを設定します。
2. **Next.js は静的書き出し**
   サーバーを常時動かさないので、費用が安く、仕組みも単純になります。
3. **権限は「カスタムクレーム」で管理**
   ログインしたユーザーに「管理者」「スタッフ」の印を付け、セキュリティルールで読み書きできる範囲を制限します。
4. **お客様の個人情報は別の保管場所に分ける**
   予約データのうち、電話番号・メールは別コレクションに置き、スタッフ以外は一切読めないようにします。
   公開ページには「日付・時間枠ごとの残り人数」だけを公開します。

## 作る順番

### 第0段階：準備
- 0-1 Firebase テスト用プロジェクト作成（ユーザー作業）
- 0-2 ひな形（Next.js）作成、Firebase 接続、エミュレーター（パソコン内で動く練習用Firebase）で動作確認
- 0-3 自動公開の仕組み（GitHub に保存すると自動でテスト環境に公開）

### 第1段階：予約
1. スタッフのログイン・権限（管理者／スタッフ）、スタッフ追加画面
2. 設定（時間枠・定員・プラン）
3. 予約管理（日付ごと一覧・追加・編集・削除・ステータス）
4. 空き枠表示と定員超過の警告
5. お客様用予約ページ（サーバー側で定員チェック・入力チェック・連続送信制限）
- 第1段階のまとめ：セキュリティルールのテスト、テスト環境での実機確認（iPad/iPhone）

### 第2段階：会計・売掛・売上
6. 会計（予約からの会計・予約なし会計・商品の追加）
7. 支払方法（現金／売掛）、売掛の自動作成・取消連動
8. 売掛管理
9. 日次締め・会計履歴・取消
10. ダッシュボード
11. Airレジ CSV 取り込み

### 第3段階：レシート・領収書
12. レシート／領収書の印刷用画面
13. インボイス項目を後から足せるデータ設計（明細ごとに税区分を持てる形にしておく）

### 最後
- スタッフ向け使い方説明書
- 本番用 Firebase プロジェクトへの移行
